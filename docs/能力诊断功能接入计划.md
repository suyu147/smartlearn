# 智学方舟「能力诊断」功能接入计划书

> 版本：v1.0（一期全功能）
> 日期：2026-09-07
> 结论：smartlearn 只写「前端页面 + Next.js 薄代理路由」，匹配/推荐/简历解析等全部能力由已部署的职能洞察后端（`http://121.43.156.61`）提供，职能洞察侧零改动。

---

## 一、目标与范围

在智学方舟顶部导航栏（与「首页 AI 对话」「智能学习」并列）新增「能力诊断」入口，进入一个新功能页面，完整复刻职能洞察个人端的「能力诊断」模块，一期直接包含全部链路：

1. **技能匹配**：选择目标岗位 + 手动输入技能/学历/工作年限/证书 → 匹配总分、能力雷达图、技能差距清单、学习路径建议
2. **岗位推荐**：按当前已掌握技能推荐适配岗位，点击可切换为目标岗位
3. **简历上传解析**：上传 PDF/DOCX/TXT/MD 简历 → 服务端异步解析 → 确认解析结果 → 一键带入技能/学历/年限，参与匹配

不在一期范围：企业端批量诊断、治理管理端、模拟面试、能力图谱浏览、趋势预测、收藏夹。

---

## 二、总体架构

```
浏览器 (smartlearn 页面 /career)
        │  同源 fetch（无 CORS 问题）
        ▼
smartlearn Next.js 薄代理路由 (app/api/v1/career/*)
        │  服务端 http 转发 + 注入 Authorization
        ▼
职能洞察已部署后端 (http://121.43.156.61/api/v1)
        ├── MySQL（用户 / 简历 / 匹配报告）
        └── Neo4j 图谱（岗位 / 技能 / 匹配算法数据源）
```

架构决策：

- **职能洞察零改动**：不改其代码、不重新部署。其 CORS 仅放行自己的前端源，所以浏览器不允许直连，必须由 smartlearn 服务端代理转发。
- **薄代理无业务逻辑**：代理路由只做四件事——转发请求、注入鉴权头、透传文件流、把职能洞察的 `{code, message, data}` 信封转换为 smartlearn 客户端 `apiFetch` 已支持的响应格式。
- **复用 smartlearn 现有设施**：`lib/api-client.ts`（apiGet/apiPost/apiUpload）、shadcn/ui 组件、recharts（雷达图）、i18n 体系。

## 三、依赖的职能洞察接口（已核实）

### 3.1 免登录链路（核心匹配）

| 用途 | 接口 | 说明 |
|---|---|---|
| 岗位列表 | `GET /api/v1/jobs?page=&pageSize=&keyword=` | 目标岗位下拉数据源 |
| 手动匹配 | `POST /api/v1/matching/manual` | 入参 `targetRoleId / skills / education / experienceYears / certificates`，出参匹配得分 + 各维度明细 + 差距清单 + 学习路径；不带 `resumeId` 时免登录 |
| 岗位推荐 | `POST /api/v1/matching/recommendations` | 入参 `skills`，出参按分数排序的岗位列表 |

### 3.2 需登录链路（简历功能）

| 用途 | 接口 | 说明 |
|---|---|---|
| 登录 | `POST /api/v1/auth/login` | 职能洞察预设账号 sun2006122 / sun2006122，返回 Bearer token |
| 上传简历（异步） | `POST /api/v1/resumes` | multipart 文件上传，返回 taskId，202 状态 |
| 查询解析进度 | `GET /api/v1/tasks/{taskId}` | 前端轮询直至 completed |
| 确认解析结果 | `PUT /api/v1/resumes/{resumeId}/confirmation` | 确认后技能/学历/年限可参与匹配 |
| 我的简历列表 | `GET /api/v1/me/resumes` | 回显历史简历 |
| 删除简历 | `DELETE /api/v1/me/resumes/{resumeId}` | 管理已上传简历 |
| 已存简历匹配 | `POST /api/v1/matching/resume/{resumeId}?targetRoleId=` | 用确认后的简历直接匹配 |

### 3.3 服务健康探测

`GET /health`（经职能洞察 nginx 代理到后端）——页面加载时探测，失败则显示「职业数据服务暂不可用」的整页降级提示。

## 四、smartlearn 侧新增内容

### 4.1 环境变量（`.env`）

```
CAREER_INSIGHT_BASE_URL=http://121.43.156.61
CAREER_INSIGHT_USERNAME=user
CAREER_INSIGHT_PASSWORD=123456
```

> 密码只存在于 smartlearn 服务端环境变量中，不下发浏览器。上线前必须修改职能洞察的公开预设密码。

### 4.2 薄代理路由（`app/api/v1/career/`）

| 文件 | 转发目标 | 备注 |
|---|---|---|
| `jobs/route.ts` | `GET /api/v1/jobs` | 岗位列表 |
| `matching/manual/route.ts` | `POST /api/v1/matching/manual` | 手动匹配 |
| `matching/recommendations/route.ts` | `POST /api/v1/matching/recommendations` | 岗位推荐 |
| `matching/resume/[resumeId]/route.ts` | `POST /api/v1/matching/resume/{id}` | 已存简历匹配 |
| `resumes/route.ts` | `GET/POST /api/v1/resumes`、`GET /api/v1/me/resumes` | 上传走 FormData 流式透传 |
| `resumes/[resumeId]/route.ts` | `DELETE /api/v1/me/resumes/{id}` | 删除 |
| `resumes/[resumeId]/confirmation/route.ts` | `PUT /api/v1/resumes/{id}/confirmation` | 确认解析 |
| `tasks/[taskId]/route.ts` | `GET /api/v1/tasks/{id}` | 解析进度轮询 |
| `health/route.ts` | `GET /health` | 可用性探测 |

代理内部实现一个共享模块（如 `lib/career/insight-proxy.ts`）：

- 服务端持有职能洞察账号，**首次请求时自动登录换取 token 并缓存至过期**（职能洞察 token 有效期 12 小时），对前端完全透明——前端永远不带职能洞察的 token，自然规避两套账号体系的耦合。
- 统一解包 `{code, message, data}` 信封；职能洞察 5xx/超时转换为 smartlearn 风格错误响应。
- 上传接口设置与职能洞察一致的 10 MB 文件上限和类型白名单（PDF/DOCX/TXT/MD）。

### 4.3 服务层与类型（`lib/career/`）

- `types.ts`：`JobSummary / MatchResult / MatchGap / LearningPath / RecommendationItem / ResumeRecord / ParseTask` 等类型（参照职能洞察 `frontend/src/types/domain.ts` 的字段命名，出参尽量原样透传，减少映射成本）。
- `service.ts`：面向页面的函数封装（`listJobs / runManualMatch / recommendRoles / uploadResume / pollTask / confirmResume / listMyResumes / deleteResume / matchWithResume`），全部基于 `apiFetch` 调薄代理，内置轻量结果缓存（岗位列表 60s）。

### 4.4 页面与组件

**页面**：`app/career/page.tsx`（路由名 `career`，短且语义清晰；标题「能力诊断」）

交互流程（对齐职能洞察 MatchingView，按 smartlearn 的 shadcn/Tailwind 风格重绘）：

```
┌─────────────────────────────────────────────────┐
│ ① 目标岗位选择（Select，数据来自岗位列表）        │
├─────────────────────────────────────────────────┤
│ ② 我的画像                                       │
│   ├ 简历上传卡片：上传 → 解析进度条(轮询) →        │
│   │   技能/学历/年限编辑确认；历史简历下拉切换      │
│   └ 手动输入区：技能标签 + 学历 + 工作年限 + 证书   │
├─────────────────────────────────────────────────┤
│ ③ 匹配结果                                       │
│   ├ 总分大数字 + 结论一句话                       │
│   ├ 能力雷达图（技能/经验/学历/能力广度/综合素养）  │
│   ├ 技能差距：已匹配 / 待补齐 两栏                 │
│   └ 学习路径：阶段化建议列表                       │
├─────────────────────────────────────────────────┤
│ ④ 岗位推荐（按当前技能推荐，点击卡片切换目标岗位）  │
└─────────────────────────────────────────────────┘
```

关键状态细节：

- 简历解析成功后自动填充②的技能/学历/年限，用户可编辑后「确认」，确认状态与职能洞察 `confirmed` 字段一致。
- 修改学历/年限或切换岗位时，若有已有结果则自动重新匹配（80ms 防抖）。
- 上传后解析任务轮询间隔 1.5s，最长 120s，超时提示重试。

**组件**（放 `components/career/`）：

- `capability-radar.tsx`：五维能力雷达图（recharts RadarChart）
- `skill-gap-list.tsx`：已匹配/待补齐技能双栏
- `learning-path-card.tsx`：学习路径阶段卡片
- `resume-upload-card.tsx`：上传 + 进度轮询 + 解析结果确认
- `job-recommend-list.tsx`：推荐岗位卡片列表

### 4.5 导航与 i18n

- `components/layout/app-nav.tsx` 的 `navItems` 在 `/chat`、`/smartlearn` 之后插入：`{ href: '/career', labelKey: 'nav.career', icon: Target }`（lucide 的 `Target` 图标，与现有图标尺寸一致）。
- i18n 词条补充 `nav.career`（中文「能力诊断」/ 英文「Career Diagnosis」）及页面内文案键。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 云端 121.43.156.61 不可用 | 功能整体不可用 | 页面加载先探测 `/health`，失败显示降级提示，不影响 smartlearn 其他功能 |
| CORS | 浏览器直连被拒 | 全部请求走服务端薄代理，浏览器永远同源 |
| 职能洞察 token 过期（12h） | 简历功能 401 | 代理层捕获 401 自动重登并重试一次 |
| 两套账号体系 | 用户身份割裂 | 代理层用环境变量中的服务账号登录，对 smartlearn 用户透明；简历数据归属该服务账号 |
| 预设密码公开（123456） | 安全风险 | 密码入 `.env` 不入前端；**上线前修改职能洞察三端密码与 AUTH_SECRET** |
| 上传大文件/慢解析 | 用户等待 | 10MB 限制 + 类型白名单前置校验 + 轮询超时提示 |
| 响应格式差异 | 前端解析失败 | 代理层统一转换，类型定义按真实响应样例编写（步骤 1 存档） |

## 七、验收标准

1. 顶部导航栏出现「能力诊断」入口，与首页 AI 对话、智能学习并列；未登录状态下的显示行为与相邻入口一致。
2. 手动链路：选择岗位 → 输入 ≥1 项技能 → 返回总分、五维雷达图、已匹配/待补齐技能、学习路径。
3. 推荐链路：按技能返回推荐岗位列表，点击卡片可切换目标岗位并自动重新匹配。
4. 简历链路：上传 demo 简历 → 轮询完成 → 技能/学历/年限自动带入且可编辑确认 → 用简历匹配成功；历史简历可查看与删除。
5. 云端不可用时页面有明确降级提示，smartlearn 其余功能不受影响。
6. `pnpm lint`、`pnpm test` 全绿。
